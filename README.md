# 🛰️ Change Sentinel — Satellite Imagery Change-Detection Dashboard

A lightweight, web-based prototype that compares two images of the same
area captured at different times, highlights **candidate** visual
changes, summarises the detected regions, and produces a downloadable
Markdown report for human review.

Built for the *Change Sentinel* problem statement (Space & Defence Tech
category). The MVP uses **classical image processing** — pixel
differencing, thresholding and morphological cleanup — **not a trained
AI model**. All outputs are *candidate* differences that require
verification by a human analyst.

---

## ⚠️ What this tool is — and is not

| This tool **does** | This tool **does not** |
| --- | --- |
| Highlight where two images differ visually | Confirm that a real-world change occurred |
| Summarise candidate regions for review | Decide whether any development is legal or illegal |
| Use real geographic coordinates **when a georeferenced GeoTIFF is uploaded** | Invent latitude/longitude for ordinary JPG/PNG uploads |
| Compute RGB-based pixel statistics | Compute true NDVI (that requires a near-infrared band) |
| Run classical image processing | Use a trained AI model (none is bundled or claimed) |

---

## Features

1. **Image upload** — two side-by-side uploaders (before / after) with
   previews, decode validation, dimension and aspect-ratio warnings, and
   identical-file detection. Supports JPG, JPEG, PNG and GeoTIFF.
2. **Preprocessing** — RGB conversion, aspect-preserving downscaling to a
   user-selected maximum dimension, and an optional, *validated* global
   translation alignment (phase correlation). Alignment is only applied
   when it measurably reduces the difference; otherwise the app says so.
3. **Change detection** — mean absolute pixel difference, Gaussian
   smoothing, adjustable sensitivity threshold, morphological
   close/open cleanup, and connected-region extraction with bounding
   boxes, centroids, areas and mean intensities (image pixel coordinates).
4. **Results dashboard** — before/after views, difference-intensity map,
   highlighted overlay, and metrics: candidate region count, pixels
   flagged, percentage of pixels flagged, mean/max difference intensity.
5. **Candidate regions table** — per-region bounding box, centroid and
   area in image coordinates, with before/after crops for visual
   inspection.
6. **Geographic view (conditional)** — an interactive Folium map is shown
   **only** when the input is a georeferenced raster whose CRS and affine
   transform can be read (requires the optional `rasterio` extra).
   Ordinary JPG/PNG uploads get a clear explanation instead of a fake map.
7. **Report** — downloadable Markdown report with inputs, method,
   settings, metrics, region table (image coordinates, plus WGS84
   coordinates only when genuinely derived), limitations and recommended
   next steps.
8. **Synthetic demo data** — bundled, reproducible demo images that are
   clearly labelled as synthetic.

## Quick start

Requires Python 3.9+ (tested on Python 3.11, Windows 64-bit, with
streamlit 1.65.0, numpy 2.4.6, Pillow 12.2.0, opencv-python-headless
4.13.0.92, folium 0.20.0, streamlit-folium 0.27.4, rasterio 1.4.4).

```bash
cd change-sentinel

# create and activate a virtual environment
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS / Linux:
source .venv/bin/activate

# install dependencies
python -m pip install --upgrade pip
pip install -r requirements.txt

# run the app
streamlit run app.py
```

The browser opens at `http://localhost:8501`.

### Try it in 30 seconds

1. Click **"Load synthetic demo pair (with changes)"** in the sidebar.
2. Inspect the difference map, the overlay and the candidate regions.
3. Open the **Report** tab and download the Markdown report.
4. Click **"Load identical pair (no changes)"** to see that identical
   images produce zero candidate regions.
5. Drag the **sensitivity threshold** slider and re-analyse to see how
   the threshold changes the output.

## Demo data (synthetic — not real satellite imagery)

`sample_data/` contains images generated by `make_sample_data.py`:

| File | Description |
| --- | --- |
| `before.png` | Synthetic "aerial" scene: fields, road, water channel. Watermark: *SYNTHETIC DEMO — NOT REAL SATELLITE IMAGERY*. |
| `after.png` | Same scene plus two obvious changes: a dark rectangular structure (stands in for new construction) and a bare-soil patch (stands in for vegetation loss). |
| `identical_before.png` / `identical_after.png` | Byte-identical pair for demonstrating zero false positives. |

Regenerate them at any time (deterministic, seeded):

```bash
python make_sample_data.py
```

These images depict **no real location**. To demo with real imagery,
obtain two georeferenced scenes of the same area (e.g. Sentinel-2 or
Landsat via their public portals, respecting each provider's terms),
export the same extent in both dates, and upload them as GeoTIFFs.

## Optional geospatial extras

By default the app runs with four lightweight dependencies and shows
**image pixel coordinates**. To unlock real geographic output:

```bash
pip install rasterio folium streamlit-folium
```

Then upload a **georeferenced GeoTIFF** (a raster with a valid CRS and
affine transform). The app will:

- read the transform and CRS with Rasterio,
- convert region bounding boxes and centroids to WGS84 (EPSG:4326),
- draw the regions on an interactive OpenStreetMap map,
- include the derived coordinates in the report.

If the file has no CRS/transform, or Rasterio is missing, the app
explains why no map is shown and falls back to image coordinates.
**Coordinates are never invented.**

## Tests

```bash
pip install pytest
pytest
```

The suite covers the key acceptance scenarios:

- **Identical images produce no differences** (zero flagged pixels, zero
  regions).
- **A synthetic image with an added object produces a detectable
  candidate region** whose bounding box and centroid cover the object.
- Threshold changes change the detection output; minimum region area
  filters small regions; regions are sorted by area.
- Invalid inputs (garbage files, mismatched dimensions, bad thresholds)
  raise clear, catchable errors.
- Resizing preserves aspect ratio; incompatible aspect ratios are
  rejected, never silently stretched.
- Optional alignment reduces measured error or is reported as unreliable.
- The bundled demo pair detects both planted changes at default settings,
  and the identical demo pair detects nothing.
- Reports contain all required sections and never fabricate coordinates.

## Interpreting the metrics honestly

- **Percentage of pixels flagged** is the fraction of *image pixels*
  the algorithm flagged. It is **not** the percentage of real land area
  that changed — real-world area requires valid geospatial metadata.
- Differences can be caused by clouds, shadows, seasonal vegetation,
  illumination, compression or misalignment — all common false positives.
- "Candidate region" means *a connected area of pixels that differed
  enough to pass the threshold*. Nothing more.

## Known limitations

- Baseline is classical image processing; no trained model and no
  measured accuracy claims.
- RGB inputs only — no true NDVI (that requires a near-infrared band).
- Alignment is a single global translation; rotation, scale differences
  and perspective are not corrected.
- Multi-band GeoTIFFs are visualised with their first three bands.
- Geographic accuracy depends entirely on the uploaded file's metadata.
- Large images are downscaled (default 1024 px) before comparison.

## Future enhancements

Georeferenced batch workflows, improved registration (rotation/scale),
cloud masking, genuine NDVI from multispectral data, a pretrained
change-detection model with documented evaluation, and GeoJSON export.
